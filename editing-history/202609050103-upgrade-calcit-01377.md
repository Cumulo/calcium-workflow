# Upgrade Calcium Workflow to Calcit 0.13.77 / 将 Calcium Workflow 升级到 Calcit 0.13.77

## 中文

- 将 Calcit 与 `@calcit/procs` 升级到 0.13.77，并将 11 个直接 Calcit 依赖升级到当前已发布版本；`caps --strict --ci` 与 `caps verify --toolchain` 验证 16 个模块以及 Calcit/procs 版本一致。
- 按 0.13.77 的 nominal enum、Struct、集合、日期和显式 Unit 规则迁移应用代码；服务端 `--check-only` 从 11 个本地告警降到零。
- 新增版本化架构文档，并用 `edit scaffold --dry-run` 验证全部定义可复用、无待创建 work item；Snapshot 经精确 0.13.77 CLI 两次 canonical format 验证均无额外变化。
- 用原生 schema v2 `config/calcit-quality.cirru` 替换自定义 JSON/Node 基线，固定 GitHub Actions 到已验证 commit，并限制 `contents: read` 与 checkout 凭据持久化。
- client 7/7 与 server 10/10 定义测试通过；默认入口动态方法 1/1、server 入口 0/1，原生质量门禁通过；Node 24 + Yarn 4.12.0 immutable install 通过。
- 当前唯一阻塞是 Respo 0.16.90 的 `respo.core/decorate-defcomp` 类型告警。修复已在 Respo PR #132 合并（merge commit `33cb64e6163e73e7556d0d93f5091051b252d0b5`），但最新 release 仍是 0.16.90，因此默认 `--check-only` 与页面 codegen 按预期在该上游告警处停止。

## English

- Upgraded Calcit and `@calcit/procs` to 0.13.77 and all eleven direct Calcit dependencies to their current published releases. `caps --strict --ci` and `caps verify --toolchain` validate all 16 modules and the matching Calcit/procs versions.
- Migrated application code to the 0.13.77 nominal-enum, Struct, collection, date, and explicit-Unit rules. Server `--check-only` went from eleven local warnings to zero.
- Added a versioned architecture plan and verified with `edit scaffold --dry-run` that every definition is reusable and no work item is missing. Two canonical-format checks with the exact 0.13.77 CLI produced no further Snapshot changes.
- Replaced the custom JSON/Node baseline with native schema-v2 `config/calcit-quality.cirru`, pinned GitHub Actions to verified commits, limited permissions to `contents: read`, and disabled persisted checkout credentials.
- All 7 client and 10 server definition tests pass. Dynamic-method budgets pass at 1/1 for the default entry and 0/1 for the server entry; the native quality gate passes; Node 24 plus Yarn 4.12.0 immutable installation passes.
- The only remaining blocker is the `respo.core/decorate-defcomp` type warning in published Respo 0.16.90. Its fix is merged in Respo PR #132 (merge commit `33cb64e6163e73e7556d0d93f5091051b252d0b5`), but the latest release remains 0.16.90, so default `--check-only` and page codegen correctly stop at that upstream warning.
