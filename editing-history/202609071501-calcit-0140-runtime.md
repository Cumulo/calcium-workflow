# Calcit 0.14.0 runtime migration / Calcit 0.14.0 运行时迁移

- Pin the native Calcit toolchain and `@calcit/procs` runtime to the latest
  `0.14.0` release; `caps upgrade --all` confirms every direct Calcit module is
  already at its latest published version.
- Use the documented `--compat-types` migration bridge in development and CI
  while preserving the existing quality baseline. Add concrete schemas and
  adapters around ports, site configuration, WebSocket callbacks, timestamps,
  and client-cache removal so both client and server compatibility checks are
  warning-free.
- Decode missing, legacy and nominal `Option<String>` persistence values through
  one typed boundary. Add a database-level serialize/parse/decode regression so
  a legitimate nominal `Db` is not discarded during server restart.
- Work around Calcit 0.14.0's incorrect JavaScript lowering of the direct generic
  `MapEntryDecision` constructor by using its explicit nominal enum form and the
  concrete `Element` payload type.
- 将原生 Calcit 工具链和 `@calcit/procs` 运行时固定到最新正式版 `0.14.0`；
  `caps upgrade --all` 已确认所有直接 Calcit 模块均为各自最新发布版本。
- 在开发与 CI 中使用官方的 `--compat-types` 迁移桥接，同时保留现有质量基线；
  为端口、站点配置、WebSocket 回调、时间戳和客户端缓存删除补齐具体边界，令
  client/server 兼容检查均无告警通过。
- 通过统一的类型化边界解码缺失、旧式及具名 `Option<String>` 持久化值，并新增
  数据库级序列化、解析、再解码回归，确保服务重启时不会丢弃合法的具名 `Db`。
- 针对 Calcit 0.14.0 将直接泛型 `MapEntryDecision` 构造错误生成为 JavaScript
  函数调用的问题，改用显式具名枚举形式和具体 `Element` payload 类型。

Runtime verification on 2026-09-07 used Calcit CLI 0.14.0 and
`@calcit/procs` 0.14.0: the server listened on port 5021, restored the existing
`storage.cirru`, accepted browser WebSocket sessions, and a fresh Vite page
rendered the Calcium login UI without console errors.

2026-09-07 的运行时验证使用 Calcit CLI 0.14.0 与 `@calcit/procs` 0.14.0：服务
在 5021 端口监听并恢复现有 `storage.cirru`，接受浏览器 WebSocket 会话；全新
Vite 页面成功渲染 Calcium 登录界面且控制台无错误。
